## Introduction

JavaScript provides four powerful collection types beyond plain objects and arrays: Map, Set, WeakMap, and WeakSet. Each serves distinct purposes and offers unique performance characteristics for specific use cases.

This guide explores when to use each collection, their internal mechanics, and practical patterns for real-world applications.

## Understanding JavaScript Collections: Core Concepts

### Map vs Object

Map is a key-value collection with important differences from plain objects:

```javascript
// Object keys are always strings/symbols
const obj = {};
obj[1] = 'one';
obj['1'] = 'ONE'; // Overwrites the number key
console.log(obj); // { '1': 'ONE' }

// Map keys can be any type
const map = new Map();
map.set(1, 'one');
map.set('1', 'ONE');
map.set(true, 'yes');
map.set({ id: 1 }, 'object key');

console.log(map.get(1)); // 'one'
console.log(map.get('1')); // 'ONE'
console.log(map.size); // 4
```

### Set: Unique Values

Set stores unique values of any type:

```javascript
// Remove duplicates from array
const numbers = [1, 2, 3, 2, 1, 4, 5, 4];
const unique = [...new Set(numbers)];
console.log(unique); // [1, 2, 3, 4, 5]

// Set operations
const setA = new Set([1, 2, 3, 4]);
const setB = new Set([3, 4, 5, 6]);

// Union
const union = new Set([...setA, ...setB]);

// Intersection
const intersection = new Set([...setA].filter(x => setB.has(x)));

// Difference
const difference = new Set([...setA].filter(x => !setB.has(x)));
```

## Architecture and Design Patterns

### Map Operations

```javascript
const userMap = new Map();

// Set values
userMap.set('user:1', { name: 'John', age: 30 });
userMap.set('user:2', { name: 'Jane', age: 25 });

// Get values
const user = userMap.get('user:1');

// Check existence
if (userMap.has('user:1')) {
    console.log('User found');
}

// Delete entries
userMap.delete('user:1');

// Iterate entries
for (const [key, value] of userMap) {
    console.log(key, value);
}

// Convert to/from array
const entries = [...userMap];
const mapFromArray = new Map(entries);
```

### WeakMap: Garbage-Collection-Friendly Maps

WeakMap only accepts object keys and allows garbage collection:

```javascript
// Private data storage
const privateData = new WeakMap();

class User {
    constructor(name, age) {
        this.name = name;
        privateData.set(this, { age });
    }
    
    getAge() {
        return privateData.get(this).age;
    }
    
    setAge(age) {
        privateData.get(this).age = age;
    }
}

const user = new User('John', 30);
console.log(user.getAge()); // 30
// user object can be garbage collected when no longer referenced
```

### WeakSet: Object-Only Sets

WeakSet stores unique objects and allows garbage collection:

```javascript
// Track visited nodes
const visited = new WeakSet();

function traverse(node) {
    if (visited.has(node)) return;
    visited.add(node);
    
    for (const child of node.children) {
        traverse(child);
    }
}

// Mark objects as processed
const processed = new WeakSet();

function processObject(obj) {
    if (processed.has(obj)) return;
    processed.add(obj);
    // Process the object
}
```

## Step-by-Step Implementation

### Caching with Map

```javascript
class MemoCache {
    constructor(maxSize = 100) {
        this.cache = new Map();
        this.maxSize = maxSize;
    }
    
    get(key) {
        if (!this.cache.has(key)) return undefined;
        
        // Move to end (most recently used)
        const value = this.cache.get(key);
        this.cache.delete(key);
        this.cache.set(key, value);
        
        return value;
    }
    
    set(key, value) {
        if (this.cache.has(key)) {
            this.cache.delete(key);
        } else if (this.cache.size >= this.maxSize) {
            // Remove oldest entry
            const firstKey = this.cache.keys().next().value;
            this.cache.delete(firstKey);
        }
        
        this.cache.set(key, value);
    }
    
    has(key) {
        return this.cache.has(key);
    }
    
    clear() {
        this.cache.clear();
    }
}

// Usage
const cache = new MemoCache(50);
cache.set('user:1', { name: 'John' });
cache.get('user:1');
```

### Event Emitter with Map

```javascript
class EventEmitter {
    constructor() {
        this.listeners = new Map();
    }
    
    on(event, callback) {
        if (!this.listeners.has(event)) {
            this.listeners.set(event, new Set());
        }
        
        this.listeners.get(event).add(callback);
        
        // Return unsubscribe function
        return () => {
            this.listeners.get(event)?.delete(callback);
        };
    }
    
    emit(event, ...args) {
        if (!this.listeners.has(event)) return;
        
        for (const callback of this.listeners.get(event)) {
            callback(...args);
        }
    }
    
    once(event, callback) {
        const unsubscribe = this.on(event, (...args) => {
            unsubscribe();
            callback(...args);
        });
        return unsubscribe;
    }
}
```

### Object Pool with WeakSet

```javascript
class ObjectPool {
    constructor(factory, reset) {
        this.factory = factory;
        this.reset = reset;
        this.available = [];
        this.inUse = new WeakSet();
    }
    
    acquire() {
        let obj;
        
        if (this.available.length > 0) {
            obj = this.available.pop();
        } else {
            obj = this.factory();
        }
        
        this.inUse.add(obj);
        return obj;
    }
    
    release(obj) {
        if (!this.inUse.has(obj)) return;
        
        this.inUse.delete(obj);
        this.reset(obj);
        this.available.push(obj);
    }
    
    get size() {
        return this.available.length;
    }
}
```

## Real-World Use Cases

### State Management

```javascript
// Reactive state with Map
class Store {
    constructor(initialState = {}) {
        this.state = new Map(Object.entries(initialState));
        this.listeners = new Map();
    }
    
    get(key) {
        return this.state.get(key);
    }
    
    set(key, value) {
        const oldValue = this.state.get(key);
        this.state.set(key, value);
        
        if (this.listeners.has(key)) {
            for (const listener of this.listeners.get(key)) {
                listener(value, oldValue);
            }
        }
    }
    
    subscribe(key, listener) {
        if (!this.listeners.has(key)) {
            this.listeners.set(key, new Set());
        }
        this.listeners.get(key).add(listener);
        
        return () => this.listeners.get(key).delete(listener);
    }
}
```

### DOM Element Tracking

```javascript
// Track element metadata without modifying DOM
const elementData = new WeakMap();

function setElementData(element, key, value) {
    if (!elementData.has(element)) {
        elementData.set(element, new Map());
    }
    elementData.get(element).set(key, value);
}

function getElementData(element, key) {
    return elementData.get(element)?.get(key);
}

// Usage
const button = document.querySelector('#myButton');
setElementData(button, 'clickCount', 0);

button.addEventListener('click', () => {
    const count = getElementData(button, 'clickCount') + 1;
    setElementData(button, 'clickCount', count);
    console.log(`Clicked ${count} times`);
});
```

## Best Practices for Production

1. **Use Map for non-string keys**: When keys are objects, numbers, or mixed types.

2. **Use Map for frequent additions/deletions**: Map is optimized for dynamic collections.

3. **Use Set for uniqueness checks**: Faster than array.includes() for large collections.

4. **Use WeakMap for object metadata**: Prevents memory leaks when objects are garbage collected.

5. **Use WeakSet for tracking visited objects**: Useful in graph traversal algorithms.

6. **Choose based on iteration needs**: Use Map/Set when you need to iterate, WeakMap/WeakSet when you don't.

## Common Pitfalls and Solutions

| Pitfall | Impact | Solution |
|---------|--------|----------|
| Using object as Map key | String coercion | Use Map for non-string keys |
| Memory leaks with Map | Unbounded growth | Use WeakMap for object keys |
| Iterating WeakMap/WeakSet | Not possible | Use regular Map/Set when iteration needed |
| Forgetting to clean up | Memory leaks | Implement cleanup patterns |

```javascript
// Pitfall: Object key coercion
const cache = {};
cache[{ id: 1 }] = 'value';
console.log(cache[{ id: 1 }]); // undefined (different string representation)

// Solution: Use Map
const map = new Map();
const key = { id: 1 };
map.set(key, 'value');
console.log(map.get(key)); // 'value'
```

## Performance Optimization

### Choosing the Right Collection

```javascript
// Performance comparison
const iterations = 1000000;

// Object lookup: O(1) average
const objStart = performance.now();
const obj = {};
for (let i = 0; i < iterations; i++) obj[i] = i;
for (let i = 0; i < iterations; i++) obj[i];
console.log(`Object: ${performance.now() - objStart}ms`);

// Map lookup: O(1) guaranteed
const mapStart = performance.now();
const map = new Map();
for (let i = 0; i < iterations; i++) map.set(i, i);
for (let i = 0; i < iterations; i++) map.get(i);
console.log(`Map: ${performance.now() - mapStart}ms`);

// Set lookup: O(1)
const setStart = performance.now();
const set = new Set();
for (let i = 0; i < iterations; i++) set.add(i);
for (let i = 0; i < iterations; i++) set.has(i);
console.log(`Set: ${performance.now() - setStart}ms`);
```

## Performance Characteristics

Understanding the performance characteristics of each data structure helps you choose the right one for your use case. Map and Set provide O(1) average time complexity for get, set, has, and delete operations, which is comparable to plain objects for small datasets but significantly faster for large datasets with frequent additions and deletions. Map maintains insertion order efficiently, making it suitable for ordered iteration patterns. Set operations like union, intersection, and difference can be implemented efficiently using the built-in methods. WeakMap and WeakSet have the same O(1) complexity for individual operations but with the added benefit of automatic garbage collection. The tradeoff is that you cannot iterate over them or check their size. In benchmarks, Map outperforms plain objects when keys are frequently added and removed, while plain objects are faster for static key sets that are defined once and read many times.

### Choosing the Right Data Structure

Selecting between Map, Set, WeakMap, and WeakSet depends on your use case. Use Map when you need key-value pairs with any type of key and need to iterate over entries. Use Set when you need a collection of unique values and need to check membership efficiently. Use WeakMap when you need to associate data with objects without preventing garbage collection, such as caching computed values for DOM elements. Use WeakSet when you need to track which objects have been processed without preventing garbage collection. The Weak variants are particularly useful for avoiding memory leaks in long-running applications where objects are created and destroyed dynamically.

### Performance Characteristics

Understanding the performance characteristics of these data structures helps you make informed choices. Map and Set provide constant time complexity for get, set, has, and delete operations in the average case. However, performance can degrade if the hash function produces many collisions. Object keys in Map are compared by reference, not by value, which means two objects with identical properties are treated as different keys. WeakMap and WeakSet have the same time complexity as their non-weak counterparts but with the additional benefit of allowing garbage collection. For large datasets, Map and Set generally outperform plain objects and arrays for lookup operations because they use hash tables internally rather than linear search.

### Serialization and Storage

Map and Set cannot be directly serialized to JSON because JSON does not support these types. Implement custom serialization by converting Map entries to an array of key-value pairs and converting Set values to an array. For Map objects, use Array.from(map.entries()) to create a serializable representation and new Map(parsed.entries) to deserialize. For Set objects, use Array.from(set) and new Set(parsed). Store serialized Map and Set data in localStorage, IndexedDB, or send it over the network as regular JSON. Be aware that WeakMap and WeakSet cannot be serialized because their entries are weakly held and may be garbage collected at any time.

### Real-World Applications

These data structures solve common real-world problems efficiently. Use Map to implement LRU caches where you need to track insertion order and remove the oldest entry when the cache is full. Use Set to deduplicate arrays of objects by a specific property, creating a new Set with custom comparison logic. Use WeakMap to attach metadata to DOM elements without modifying the elements themselves, which is how many UI frameworks track component state. Use WeakSet to track which objects have been visited during graph traversal, preventing infinite loops in circular data structures. These patterns appear frequently in production codebases and understanding when to use each data structure improves code quality and performance.

Choosing the right data structure depends on whether you need key-value mapping, unique value tracking, or automatic garbage collection of unreferenced entries.

## Conclusion

JavaScript's collection types provide powerful alternatives to plain objects and arrays. Choose Map for complex key-value storage, Set for uniqueness, WeakMap for object metadata, and WeakSet for tracking object states.

Key takeaways:
1. Map supports any key type and maintains insertion order
2. Set automatically handles uniqueness
3. WeakMap/WeakSet prevent memory leaks for object references
4. Choose based on key types, iteration needs, and memory concerns
5. Collections provide better performance for specific use cases
