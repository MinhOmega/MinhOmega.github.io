## Introduction

The Web Codecs API provides low-level access to browser media encoders and decoders, enabling frame-by-frame processing of audio and video. Unlike the `<video>` element which handles everything internally, Web Codecs gives you raw frames and audio data to process, transform, or stream. This API is essential for building video editors, real-time streaming applications, computer vision systems, and custom media pipelines.

This guide covers video encoding/decoding, audio processing, and real-world use cases.

## Architecture Overview

### Web Codecs Pipeline

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│ Camera/  │────>│ Video    │────>│ Process  │────>│ Video    │──> Output
│ File     │     │ Decoder  │     │ Frames   │     │ Encoder  │
└──────────┘     └──────────┘     └──────────┘     └──────────┘
```

### Key Classes

| Class | Purpose |
|-------|---------|
| `VideoDecoder` | Decode compressed video to raw frames |
| `VideoEncoder` | Encode raw frames to compressed video |
| `AudioDecoder` | Decode compressed audio to raw PCM |
| `AudioEncoder` | Encode raw PCM to compressed audio |
| `VideoFrame` | Raw video frame data |
| `AudioData` | Raw audio sample data |
| `EncodedVideoChunk` | Compressed video data |
| `EncodedAudioChunk` | Compressed audio data |

## Video Decoding

### Decode Video Frames

```typescript
const decoder = new VideoDecoder({
  output: (frame: VideoFrame) => {
    // Process each decoded frame
    console.log('Frame:', frame.timestamp, frame.displayWidth, frame.displayHeight);
    
    // Draw to canvas
    const canvas = document.querySelector('canvas')!;
    const ctx = canvas.getContext('2d')!;
    ctx.drawImage(frame, 0, 0);
    frame.close(); // Release memory
  },
  error: (e: DOMException) => {
    console.error('Decode error:', e);
  },
});

decoder.configure({
  codec: 'avc1.64001E', // H.264 High Profile
  codedWidth: 1920,
  codedHeight: 1080,
});

// Feed encoded chunks
const chunk = new EncodedVideoChunk({
  type: 'key',
  timestamp: 0,
  data: encodedData,
});
decoder.decode(chunk);
```

## Video Encoding

### Encode Raw Frames

```typescript
const encoder = new VideoEncoder({
  output: (chunk: EncodedVideoChunk, metadata?: EncodedVideoChunkMetadata) => {
    // Process encoded chunk
    const data = new Uint8Array(chunk.byteLength);
    chunk.copyTo(data);
    
    // Send to server or write to file
    sendToServer(data, chunk.timestamp, chunk.type);
  },
  error: (e: DOMException) => {
    console.error('Encode error:', e);
  },
});

encoder.configure({
  codec: 'avc1.64001E',
  width: 1920,
  height: 1080,
  bitrate: 5_000_000,
  framerate: 30,
});

// Encode frames from canvas
const canvas = document.querySelector('canvas')!;
const frame = new VideoFrame(canvas, { timestamp: performance.now() * 1000 });
encoder.encode(frame, { keyFrame: true });
frame.close();
```

## Audio Processing

### Decode Audio

```typescript
const audioDecoder = new AudioDecoder({
  output: (data: AudioData) => {
    // Process audio samples
    const samples = new Float32Array(data.numberOfFrames);
    data.copyTo(samples, { planeIndex: 0 });
    
    // Play through Web Audio API
    const audioCtx = new AudioContext();
    const buffer = audioCtx.createBuffer(
      data.numberOfChannels,
      data.numberOfFrames,
      data.sampleRate
    );
    // Copy data to buffer...
    data.close();
  },
  error: console.error,
});

audioDecoder.configure({
  codec: 'mp4a.40.2',
  sampleRate: 44100,
  numberOfChannels: 2,
});
```

## Real-World Use Cases

### Screen Recording

```typescript
async function startScreenRecording() {
  const stream = await navigator.mediaDevices.getDisplayMedia({
    video: { width: 1920, height: 1080 },
  });

  const track = stream.getVideoTracks()[0];
  const reader = track.getReader();

  const encoder = new VideoEncoder({
    output: (chunk) => {
      // Accumulate chunks for final file
      chunks.push(chunk);
    },
    error: console.error,
  });

  encoder.configure({
    codec: 'avc1.64001E',
    width: 1920,
    height: 1080,
    bitrate: 8_000_000,
  });

  // Process frames
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    const frame = new VideoFrame(value, {
      timestamp: performance.now() * 1000,
    });
    encoder.encode(frame);
    frame.close();
  }

  await encoder.flush();
  encoder.close();
}
```

async function applyFilter(source: HTMLVideoElement, canvas: HTMLCanvasElement) {

    const frame = new VideoFrame(value, {
      timestamp: performance.now() * 1000,

    // Process frame...
    frame.close();
    value.close();
  }
}

## Best Practices

1. **Always close frames**: `frame.close()` releases memory
2. **Check codec support**: Use `VideoDecoder.isConfigSupported()`
3. **Handle errors**: Decoders/encoders can fail
4. **Manage memory**: Process frames in batches
5. **Use hardware acceleration**: Browser uses GPU when available

## Common Pitfalls

| Pitfall | Impact | Solution |
|---------|--------|----------|
| Not closing frames | Memory leak | Always call close() |
| Unsupported codec | Decode fails | Check isConfigSupported() |
| Buffer overflow | Frames dropped | Process fast enough |
| Missing timestamp | Sync issues | Always set timestamp |

### Browser Support and Fallbacks

The Web Codecs API is available in Chromium-based browsers including Chrome, Edge, and Opera. Firefox has partial support with ongoing development. Safari added support in version sixteen point four. For browsers that do not support Web Codecs, implement fallback strategies using MediaSource Extensions or server-side transcoding. Use feature detection to check for the availability of VideoEncoder and VideoDecoder before using them. Provide a degraded experience for unsupported browsers rather than failing completely, such as using pre-transcoded video files instead of real-time encoding.

### Encoding and Decoding Pipelines

The Web Codecs API provides separate interfaces for encoding and decoding audio and video. VideoDecoder takes encoded video chunks and produces raw video frames in formats like I420 or NV12. VideoEncoder takes raw video frames and produces encoded chunks in formats like VP8, VP9, H.264, or AV1. AudioDecoder and AudioEncoder work similarly for audio data. You chain these components together to build processing pipelines. For example, read encoded video from a file, decode it to raw frames, apply transformations using WebGL or Canvas, re-encode the transformed frames, and write the result to a new file. This pipeline approach gives you complete control over each stage of the processing.

### Real-Time Processing

The Web Codecs API enables real-time video processing for applications like video conferencing, live streaming, and augmented reality. Capture video from a camera using getUserMedia, feed the frames into a VideoEncoder for real-time compression, and transmit the encoded chunks over WebRTC or WebTransport. On the receiving end, decode the chunks and display them using a canvas element or video element. The key to real-time performance is managing the encoding latency by configuring the encoder with appropriate bitrate, framerate, and latency mode settings. Use hardware acceleration when available to ensure that encoding and decoding do not consume excessive CPU resources.

### Working with Canvas

The Web Codecs API integrates closely with the Canvas API for video frame manipulation. Create a VideoFrame from a canvas element using the VideoFrame constructor with the canvas as the source. Draw a VideoFrame onto a canvas using the drawImage method. This integration enables powerful video processing workflows like adding overlays, applying filters, compositing multiple video streams, and generating thumbnails. Use OffscreenCanvas in web workers to perform these operations without blocking the main thread. The combination of Web Codecs and Canvas provides a complete video processing toolkit that runs entirely in the browser.

### Audio Processing

The Web Codecs API includes AudioEncoder and AudioDecoder for processing audio data. AudioEncoder takes raw audio data in PCM format and produces encoded audio chunks in formats like Opus, AAC, or FLAC. AudioDecoder reverses the process, producing raw audio from encoded chunks. Use AudioData objects to represent raw audio with specific sample formats, sample rates, and channel configurations. Process audio captured from the microphone by encoding it in real-time for transmission over WebRTC or WebTransport. Decode received audio chunks and play them using the Web Audio API. The Web Codecs audio interfaces provide lower latency and more control than the older MediaStream Recording API.

### Codec Configuration

Configuring encoders and decoders correctly is essential for achieving the desired quality and performance. For video encoding, specify the codec string, dimensions, bitrate, framerate, and latency mode. Hardware encoder configurations may differ from software encoders, so check the isConfigSupported method before creating the encoder. For audio encoding, specify the codec, sample rate, number of channels, and bitrate. Use the ABR (Adaptive Bitrate) encoder mode for streaming applications where the available bandwidth may change. Configure decoders with the codec string and any codec-specific configuration data extracted from the container format. Properly configured codecs produce higher quality output with lower latency and fewer artifacts.

### File Format Integration

The Web Codecs API works with raw encoded chunks and does not handle container formats like MP4, WebM, or MKV directly. Use the MP4Box.js library to demux MP4 files into individual video and audio chunks for decoding. Use the WebM muxer library to combine encoded chunks into WebM files for export. For real-time streaming, the encoded chunks are transmitted directly over WebRTC or WebTransport without container wrapping. Understanding the distinction between codecs and containers is important because the Web Codecs API handles the codec layer while you need additional libraries for container format handling. This separation provides flexibility to work with any combination of codec and container format.

### WebRTC Integration

The Web Codecs API integrates naturally with WebRTC for real-time communication applications. Use VideoEncoder to encode camera frames with low-latency settings optimized for real-time transmission. Pass the encoded chunks to the WebRTC sender for transmission over the peer connection. On the receiving end, use VideoDecoder to decode the received chunks and display them. This integration gives you fine-grained control over the encoding parameters, allowing you to adapt quality based on network conditions. Implement simulcast by encoding the same input at multiple resolutions and bitrates, allowing the receiver to select the appropriate quality stream based on their bandwidth and display size.

### Screen Recording and Capture

Building screen recording applications is straightforward with the Web Codecs API. Use the getDisplayMedia API to capture the screen, then feed the captured frames into a VideoEncoder for efficient compression. Combine the encoded video chunks with encoded audio from the microphone to create a complete recording. Use a MediaRecorder alternative built on Web Codecs for more control over encoding quality, format, and file size. Store the encoded chunks in IndexedDB for long recordings that exceed available memory, then combine them into a final file when the recording is complete. This approach produces higher quality recordings with smaller file sizes compared to the default MediaRecorder.

### Accessibility and Media Processing

The Web Codecs API enables accessibility features that improve the experience for users with disabilities. Generate real-time captions by processing audio through a speech recognition model running in a Web Worker. Create audio descriptions for video content by analyzing video frames and generating descriptive text. Implement sign language overlays by compositing a sign language video stream onto the main video. Adjust video playback speed, contrast, and color balance using frame processing before display. These accessibility enhancements can be implemented entirely client-side using the Web Codecs API, reducing the need for server-side processing and enabling real-time adaptation to user preferences.

The Web Codecs API continues to evolve with new codec support and improved performance characteristics. Browser vendors are actively working on AV1 encoding support which promises better compression efficiency than H.264 for video conferencing and streaming applications.

The WebCodecs API unlocks hardware-accelerated media processing directly in the browser, enabling applications like video editors and real-time streaming tools.
