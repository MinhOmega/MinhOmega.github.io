## Introduction

The Interop project is a collaboration between browser vendors (Google, Apple, Microsoft, Mozilla) and other stakeholders to improve cross-browser compatibility. Each year, they select focus areas where browsers should align their implementations. The 2025 focus areas represent the most ambitious effort yet, targeting features that will make the web platform more consistent and capable.

This guide covers the Interop 2025 focus areas, what they mean for developers, and how to use the newly interoperable features.

## What is Interop?

Interop is an annual initiative where browser vendors agree on a set of web platform features to focus on improving. Each focus area has specific tests that all browsers must pass. The goal is to eliminate cross-browser inconsistencies that frustrate developers and fragment the web.

The Interop project tracks progress with a public dashboard showing each browser's score across all focus areas.

## Interop 2025 Focus Areas

### CSS Anchor Positioning

CSS Anchor Positioning lets you position elements relative to other elements (anchors) without JavaScript.

```css
/* Define an anchor */
.trigger {
  anchor-name: --trigger;
}

/* Position relative to the anchor */
.tooltip {
  position: fixed;
  position-anchor: --trigger;
  top: anchor(bottom);
  left: anchor(center);
  translate: -50% 8px;
}

/* Fallback positioning */
.tooltip {
  position-try-fallbacks: flip-block, flip-inline, flip-block flip-inline;
}

/* Position using inset-area shorthand */
.dropdown {
  position: fixed;
  position-anchor: --menu-button;
  inset-area: block-end span-inline-end;
}
```

### Scroll-Driven Animations

Animations driven by scroll position instead of time.

```css
/* Animate based on scroll position */
.progress-bar {
  animation: grow-width linear;
  animation-timeline: scroll();
}

@keyframes grow-width {
  from { width: 0; }
  to { width: 100%; }
}

/* Animate elements as they scroll through the viewport */
.fade-in {
  animation: fade-in linear;
  animation-timeline: view();
  animation-range: entry 0% entry 100%;
}

@keyframes fade-in {
  from { opacity: 0; transform: translateY(20px); }
  to { opacity: 1; transform: translateY(0); }
}
```

### View Transitions Level 2

Cross-document view transitions for multi-page applications.

```css
/* Enable cross-document view transitions */
@view-transition {
  navigation: auto;
}

/* Customize transition animations */
::view-transition-old(root) {
  animation: fade-out 0.3s ease-out;
}

::view-transition-new(root) {
  animation: fade-in 0.3s ease-in;
}
```

### Invoker Commands

Declarative command invocation without JavaScript.

```html
<!-- Toggle a dialog -->
<button commandfor="my-dialog" command="show-modal">Open Dialog</button>
<dialog id="my-dialog">
  <p>Dialog content</p>
  <button commandfor="my-dialog" command="close">Close</button>
</dialog>

<!-- Toggle visibility -->
<button commandfor="details" command="toggle-open">Toggle</button>
<div id="details">Hidden content</div>
```

### Speculation Rules API

Tell the browser which pages to prefetch or prerender.

```html
<script type="speculationrules">
{
  "prerender": [
    {
      "where": {
        "href_matches": "/products/*"
      },
      "eagerness": "moderate"
    }
  ],
  "prefetch": [
    {
      "where": {
        "href_matches": "/blog/*"
      },
      "eagerness": "conservative"
    }
  ]
}
</script>
```

### Dialog toggle and customize

Enhanced `<dialog>` element with better customization.

```css
/* Customize dialog backdrop */
dialog::backdrop {
  background: rgba(0, 0, 0, 0.5);
  backdrop-filter: blur(4px);
}

/* Open state animation */
dialog[open] {
  animation: dialog-in 0.2s ease-out;
}

dialog:not([open]) {
  animation: dialog-out 0.2s ease-in;
}

@keyframes dialog-in {
  from { opacity: 0; transform: scale(0.95); }
  to { opacity: 1; transform: scale(1); }
}
```

### @starting-style

Define styles for when an element is first rendered or transitions from `display: none`.

```css
/* Animate elements on first render */
.dialog[open] {
  opacity: 1;
  transform: scale(1);
  transition: opacity 0.2s, transform 0.2s;
}

@starting-style {
  .dialog[open] {
    opacity: 0;
    transform: scale(0.9);
  }
}

/* Animate popovers */
[popover]:popover-open {
  opacity: 1;
  transform: translateY(0);
  transition: opacity 0.2s, transform 0.2s, display 0.2s allow-discrete;
}

@starting-style {
  [popover]:popover-open {
    opacity: 0;
    transform: translateY(-10px);
  }
}
```

### Exclusive Accordion

Native exclusive accordion behavior without JavaScript.

```html
<details name="faq">
  <summary>What is web development?</summary>
  <p>Web development is the process of building websites and web applications.</p>
</details>

<details name="faq">
  <summary>What is CSS?</summary>
  <p>CSS is a style sheet language for describing the presentation of web pages.</p>
</details>

<details name="faq">
  <summary>What is JavaScript?</summary>
  <p>JavaScript is a programming language for the web.</p>
</details>
```

When one `<details>` is opened, others with the same `name` attribute automatically close.

### :user-valid and :user-invalid

Style form elements based on user interaction, not just validity state.

```css
/* Only show validation styles after user interaction */
input:user-valid {
  border-color: green;
}

input:user-invalid {
  border-color: red;
}

/* Different from :valid/:invalid which apply immediately */
input:valid {
  /* Always applied when valid */
}
```

## Step-by-Step Adoption

### Step 1: Check Browser Support

```javascript
// Feature detection for CSS Anchor Positioning
if (CSS.supports('anchor-name', '--test')) {
  // Use anchor positioning
}

// Feature detection for scroll-driven animations
if (CSS.supports('animation-timeline', 'scroll()')) {
  // Use scroll-driven animations
}
```

### Step 2: Use Progressive Enhancement

```css
/* Base styles without anchor positioning */
.tooltip {
  position: fixed;
  top: 50%;
  left: 50%;
}

/* Enhanced styles with anchor positioning */
@supports (anchor-name: --test) {
  .trigger {
    anchor-name: --trigger;
  }
  .tooltip {
    position-anchor: --trigger;
    top: anchor(bottom);
    left: anchor(center);
  }
}
```

### Step 3: Update Your Browser Support Policy

```json
// .browserslistrc
> 0.5%
last 2 versions
not dead
not op_mini all
```

## Best Practices

1. **Use progressive enhancement**: Provide fallbacks for newer features
2. **Check the Interop dashboard**: Track which features are ready for production
3. **Feature detect**: Use `CSS.supports()` and feature detection before using new APIs
4. **Test across browsers**: Even interoperable features may have edge cases
5. **Update polyfills**: Remove polyfills for features that are now interoperable

## Common Pitfalls

| Pitfall | Impact | Solution |
|---------|--------|----------|
| Using features before Interop | Broken in some browsers | Check Interop dashboard |
| Not providing fallbacks | Broken in older browsers | Use @supports for progressive enhancement |
| Ignoring edge cases | Inconsistent behavior | Test thoroughly across browsers |
| Keeping old polyfills | Unnecessary bundle size | Remove polyfills for Interop features |

### Testing Strategies

Effective cross-browser testing in twenty twenty five combines automated and manual approaches. Use Playwright or Selenium to run your test suite across Chromium, Firefox, and WebKit engines. BrowserStack or Sauce Labs provide access to real devices and browser versions for manual testing. Focus manual testing on areas where browser differences are most likely: CSS layout, form inputs, media playback, and accessibility. Use the Web Platform Tests dashboard to check whether specific features pass tests in each browser. Set up visual regression testing to catch layout differences between browsers that automated functional tests might miss.
### CSS Interop Improvements

CSS interoperability has improved dramatically in recent years. The :has() selector, which enables parent selection and complex relational queries, is now available in all major browsers. CSS nesting reduces the need for preprocessors. Container queries provide component-level responsive design. Subgrid enables aligned grid layouts across nested components. The @layer at-rule manages specificity without resorting to hacks. These features eliminate common pain points that previously required browser-specific workarounds or JavaScript solutions. Test your CSS across browsers using tools like BrowserStack to catch rendering differences, but expect far fewer issues than in previous years.

### JavaScript Engine Convergence

JavaScript engine behavior has converged significantly across browsers. Features like optional chaining, nullish coalescing, and top-level await work identically across all engines. The Temporal API proposal for modern date handling is being implemented consistently across browsers. Private class fields and methods follow the same specification in all engines. This convergence means that developers can write modern JavaScript with confidence that it will behave the same way in Chrome, Firefox, and Safari. Use the ECMAScript compatibility table to verify that specific features are supported in your target browsers, and polyfill only the features that are not yet universal.

### WebAssembly Compatibility

WebAssembly support is consistent across all major browsers, with all engines supporting the core specification, SIMD instructions, and multi-threading. The garbage collection proposal for WebAssembly enables languages like Kotlin, Dart, and Java to compile to WebAssembly more efficiently. The component model proposal provides a standardized way to compose WebAssembly modules from different languages. Test your WebAssembly applications across browsers to verify that performance characteristics are acceptable, as JIT compilation strategies differ between engines and can affect execution speed for specific workloads.

### Form Controls Evolution

Form controls have received significant cross-browser improvements. The datalist element works consistently across browsers for providing autocomplete suggestions. The color input type provides a native color picker with a consistent interface. Date and time input types have improved styling and behavior across browsers. The meter and progress elements render consistently and support the same styling APIs. These improvements mean that developers can use native form controls more confidently, reducing the need for custom form control libraries. Native form controls provide better accessibility, performance, and consistency than custom implementations.

### Font and Typography Features

Modern font and typography features are now consistently supported across browsers. Variable fonts allow a single font file to contain multiple weights, widths, and styles, reducing the number of font files needed. The font-variation-settings property provides fine-grained control over variable font axes. The text-wrap balance and text-wrap pretty properties improve text rendering by balancing line lengths and avoiding orphans. The text-spacing-trim property adjusts spacing between CJK characters for better readability. These typographic improvements enable more beautiful and readable text rendering without requiring external libraries or complex CSS hacks.

### Web Components Interoperability

Web Components have achieved excellent interoperability across browsers. Custom elements, shadow DOM, and HTML templates work consistently in Chrome, Firefox, Safari, and Edge. The Declarative Shadow DOM proposal enables server-rendered web components without JavaScript. Slot assignment and named slots provide flexible content distribution. CSS custom properties pierce the shadow DOM boundary, enabling theme customization from outside the component. These interoperability improvements make Web Components a viable choice for building reusable UI libraries that work across any framework or no framework at all.

### Testing Automation

Automate cross-browser testing to catch compatibility issues before they reach production. Use Playwright to run your test suite across Chromium, Firefox, and WebKit engines in a single test run. Configure visual regression testing to detect layout differences between browsers. Set up CI pipelines that run tests on multiple browser versions including the latest stable and beta releases. Use BrowserStack or Sauce Labs for testing on real devices and browsers that are not available in your CI environment. Test your application with different user agent strings and feature flags to simulate different browser configurations. These automated testing practices ensure that your application works correctly across the browser ecosystem.

### The Baseline Concept

The Baseline initiative by the web standards community defines which web platform features are available across all major browsers. A feature that reaches Baseline Widely Available status can be used in production without polyfills or feature detection. This gives developers a clear signal about which features are safe to adopt. The Baseline concept helps teams make informed decisions about which technologies to invest in and when to drop support for older browser versions.

The Interop 2025 initiative demonstrates the browser vendors' commitment to reducing compatibility pain points for web developers through collaborative testing and specification alignment.

The Interop project has dramatically improved cross-browser compatibility.
