## Introduction

TanStack Query (formerly React Query) is the most widely used data-fetching library for React applications. Version 5, released in late 2023, represents a significant evolution with a simplified API, improved TypeScript inference, and breaking changes that require migration from v4. The most visible change is the shift from positional arguments to a single options object for hooks like `useQuery` and `useMutation`. This change, while breaking, dramatically improves TypeScript inference and makes the API more consistent and discoverable.

Beyond the API changes, v5 introduces new features that address real-world pain points: the `usePrefetchQuery` hook for prefetching data before navigation, the `placeholderData` function for showing stale data while fresh data loads, improved infinite query support with `maxPages`, and better DevTools integration. The migration from v4 to v5 is straightforward for most applications but requires attention to renamed options, changed defaults, and the new TypeScript requirements.

This guide covers every significant change in TanStack Query v5, provides before-and-after migration examples for common patterns, explains the reasoning behind each change, and shows how to leverage new features to build better data-fetching patterns. We also cover the migration path step by step, common pitfalls during migration, and testing strategies for ensuring correctness after the upgrade.

## Understanding v5 Changes: Core Concepts

### The Options Object Migration

The most impactful change in v5 is that all hooks now accept a single options object instead of positional arguments. This affects `useQuery`, `useInfiniteQuery`, `useMutation`, `queryClient.fetchQuery`, and `queryClient.prefetchQuery`.

```typescript
// v4: positional arguments
useQuery(['todos', { status }], fetchTodos, {
  staleTime: 5000,
  refetchOnWindowFocus: false,
});

// v5: single options object
useQuery({
  queryKey: ['todos', { status }],
  queryFn: fetchTodos,
  staleTime: 5000,
  refetchOnWindowFocus: false,
});
```

### Improved TypeScript Inference

The single options object enables TypeScript to infer types much better. The `queryFn` now automatically receives the correct `queryKey` type, eliminating the need for manual type annotations in most cases.

```typescript
// v5: automatic type inference
useQuery({
  queryKey: ['user', userId] as const,
  queryFn: async ({ queryKey }) => {
    const [, id] = queryKey; // TypeScript knows id is string
    const response = await fetch(`/api/users/${id}`);
    return response.json() as Promise<User>;
  },
});
```

### Changed Default Values

Several defaults changed in v5 to better reflect common usage patterns. `networkMode` defaults to `'online'` instead of `'always'`, and `gcTime` (renamed from `cacheTime`) defaults to 5 minutes for queries and 0 for mutations.

## Architecture and Design Patterns

### Query Key Factory Pattern

With v5's improved TypeScript inference, query key factories become even more powerful for type-safe data fetching.

```typescript
// Type-safe query key factory
const todoKeys = {
  all: ['todos'] as const,
  lists: () => [...todoKeys.all, 'list'] as const,
  list: (filters: TodoFilters) => [...todoKeys.lists(), filters] as const,
  details: () => [...todoKeys.all, 'detail'] as const,
  detail: (id: string) => [...todoKeys.details(), id] as const,
};

// Usage with full type safety
useQuery({
  queryKey: todoKeys.list({ status: 'active' }),
  queryFn: () => fetchTodos({ status: 'active' }),
});
```

### Optimistic Updates Pattern

```typescript
useMutation({
  mutationFn: updateTodo,
  onMutate: async (newTodo) => {
    await queryClient.cancelQueries({ queryKey: todoKeys.detail(newTodo.id) });

    const previousTodo = queryClient.getQueryData(todoKeys.detail(newTodo.id));

    queryClient.setQueryData(todoKeys.detail(newTodo.id), newTodo);

    return { previousTodo };
  },
  onError: (err, newTodo, context) => {
    queryClient.setQueryData(
      todoKeys.detail(newTodo.id),
      context?.previousTodo
    );
  },
  onSettled: (data, error, variables) => {
    queryClient.invalidateQueries({ queryKey: todoKeys.detail(variables.id) });
  },
});
```

## Step-by-Step Migration from v4 to v5

### Step 1: Update Packages

```bash
npm install @tanstack/react-query@5 @tanstack/react-query-devtools@5
```

### Step 2: Migrate useQuery Calls

```typescript
// Before (v4)
const { data } = useQuery(['user', userId], () => fetchUser(userId), {
  enabled: !!userId,
  staleTime: 1000 * 60 * 5,
});

// After (v5)
const { data } = useQuery({
  queryKey: ['user', userId],
  queryFn: () => fetchUser(userId),
  enabled: !!userId,
  staleTime: 1000 * 60 * 5,
});
```

### Step 3: Migrate useMutation Calls

```typescript
// Before (v4)
const mutation = useMutation(createTodo, {
  onSuccess: () => queryClient.invalidateQueries('todos'),
});

// After (v5)
const mutation = useMutation({
  mutationFn: createTodo,
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['todos'] }),
});
```

### Step 4: Replace cacheTime with gcTime

```typescript
// Before (v4)
useQuery(key, fn, { cacheTime: 1000 * 60 * 10 });

// After (v5)
useQuery({ queryKey: key, queryFn: fn, gcTime: 1000 * 60 * 10 });
```

### Step 5: Update Infinite Queries

```typescript
// Before (v4)
useInfiniteQuery('todos', fetchTodos, {
  getNextPageParam: (lastPage) => lastPage.nextCursor,
});

// After (v5)
useInfiniteQuery({
  queryKey: ['todos'],
  queryFn: fetchTodos,
  initialPageParam: 0,
  getNextPageParam: (lastPage) => lastPage.nextCursor,
});
```

## Real-World Use Cases

### Use Case 1: Prefetching on Hover

```typescript
function TodoList() {
  const queryClient = useQueryClient();

  const handleMouseEnter = (id: string) => {
    queryClient.prefetchQuery({
      queryKey: todoKeys.detail(id),
      queryFn: () => fetchTodo(id),
      staleTime: 1000 * 60 * 5,
    });
  };

  return todos.map(todo => (
    <Link to={`/todos/${todo.id}`} onMouseEnter={() => handleMouseEnter(todo.id)}>
      {todo.title}
    </Link>
  ));
}
```

### Use Case 2: Paginated Queries with maxPages

```typescript
useInfiniteQuery({
  queryKey: ['notifications'],
  queryFn: fetchNotifications,
  initialPageParam: 1,
  getNextPageParam: (lastPage) => lastPage.nextPage,
  maxPages: 5, // Keep only 5 pages in memory
});
```

### Use Case 3: Placeholder Data

```typescript
useQuery({
  queryKey: todoKeys.detail(id),
  queryFn: () => fetchTodo(id),
  placeholderData: () => {
    // Show data from the list while detail loads
    return queryClient
      .getQueryData(todoKeys.lists())
      ?.find(todo => todo.id === id);
  },
});
```

## Best Practices for Production

1. **Migrate incrementally**: v4 and v5 can coexist using the `@tanstack/react-query` v5 package with the `@tanstack/react-query-v4` compatibility shim.
2. **Use query key factories**: Type-safe query key factories prevent key mismatches and improve refactoring confidence.
3. **Leverage improved TypeScript**: Let TypeScript infer types from `queryKey` and `queryFn` instead of manually annotating.
4. **Use `gcTime` instead of `cacheTime`**: The rename reflects what the option actually does—controls garbage collection time.
5. **Use `networkMode: 'always'` for offline-first apps**: If your app should fetch even when offline (for service worker caching), explicitly set this.
6. **Test with `@tanstack/react-query-devtools`**: The DevTools show query states, cache contents, and refetch activity.
7. **Use `select` for data transformation**: Transform data at the query level instead of in components to avoid unnecessary re-renders.
8. **Handle errors at the query level**: Use `throwOnError` for queries that should show error boundaries, and `onError` for side effects.

## Common Pitfalls and Solutions

| Pitfall | Impact | Solution |
|---------|--------|----------|
| Using positional args (v4 style) | TypeScript errors, runtime failures | Use single options object |
| Missing `initialPageParam` in infinite queries | Runtime error | Always specify initialPageParam |
| Using `cacheTime` instead of `gcTime` | Deprecated warning | Replace with gcTime |
| Not invalidating queries after mutations | Stale data displayed | Use invalidateQueries in onSuccess |
| Over-fetching with large query keys | Unnecessary re-renders | Use select to pick only needed data |

## Performance Optimization

```typescript
// Use select to minimize re-renders
const { data: userName } = useQuery({
  queryKey: ['user', userId],
  queryFn: () => fetchUser(userId),
  select: (user) => user.name, // Only re-renders when name changes
});

// Use structuralSharing: false for non-serializable data
useQuery({
  queryKey: ['data'],
  queryFn: fetchData,
  structuralSharing: false,
});
```

## Testing Strategies

```typescript
import { renderHook, waitFor } from '@testing-library/react';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';

function createWrapper() {
  const queryClient = new QueryClient({
    defaultOptions: { queries: { retry: false } },
  });
  return ({ children }) => (
    <QueryClientProvider client={queryClient}>{children}</QueryClientProvider>
  );
}

test('fetches and displays user', async () => {
  const { result } = renderHook(
    () => useQuery({ queryKey: ['user', '1'], queryFn: () => fetchUser('1') }),
    { wrapper: createWrapper() }
  );

  expect(result.current.isLoading).toBe(true);

  await waitFor(() => expect(result.current.isSuccess).toBe(true));
  expect(result.current.data.name).toBe('John');
});
```

## Future Outlook

TanStack Query continues to evolve with framework-specific adapters (React, Vue, Svelte, Solid, Angular), server-component integration, and improved DevTools. The library is moving toward being the universal data-fetching solution across all JavaScript frameworks, with the core logic shared and only the Reactivity layer varying per framework.

## Conclusion

TanStack Query v5 is a significant improvement over v4 with a cleaner API, better TypeScript inference, and new features that address real-world data-fetching patterns. The migration is straightforward—replace positional arguments with options objects, rename `cacheTime` to `gcTime`, add `initialPageParam` to infinite queries, and update invalidation calls. The effort is minimal compared to the benefits: better type safety, more consistent API, and access to new features like `maxPages` and `placeholderData` functions.

The key migration steps are: update packages, migrate hooks to options objects, replace deprecated options, and test thoroughly. Once migrated, leverage query key factories for type safety, use `select` for data transformation, and take advantage of prefetching for instant navigation experiences.
