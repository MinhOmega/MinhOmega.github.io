## Decorator Types and Context

Apply to: class, method, field, accessor, getter/setter. Context provides: kind, name, static, private, access object. metadata API shared across decorators on a class. addInitializer for post-definition setup. Field decorators return initializer functions.

## Validation and Infrastructure

Validation decorators apply rules to fields and parameters. Libraries like class-validator provide comprehensive validation. Logging decorators auto-log entry, exit, arguments. Tracing creates OpenTelemetry spans. Performance decorators measure execution time. Caching with TTL. Retry with configurable attempts.

## Dependency Injection

![frontend illustration](https://images.unsplash.com/photo-1517180102446-f3ece451e9d8?w=800&h=400&fit=crop)

injectable marks classes for registration. inject specifies dependency tokens. Container reads metadata to resolve dependencies. Stage 3 doesn't support parameter decorators directly. Workarounds with field or class decorators. Used in NestJS, Angular, custom frameworks.

## Comparison and Best Practices

Stage 3 vs Legacy: different context API, no parameter decorators, context.metadata vs Reflect.metadata, auto-accessors new. Migration: update TypeScript 5.0+, remove experimentalDecorators. Keep decorators focused, composable, documented. Test independently. Create reusable decorator library.
